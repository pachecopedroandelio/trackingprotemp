# ProTemp V4 — Render deployment pilot

A **read-only, administrator-only** pilot connected to the TZONE API. It is **not** a customer-ready multi-tenant application. It does not create users, edit shipments, or write to TZONE.

## What works
- Password-protected administrator login
- TZONE `/Identity` token exchange, `/Device` list, `/Data/Realtime/{id}`
- Device selection, live temperature/humidity/battery, location when provided
- Satellite map and 60-second automatic refresh
- Server-side secrets and no credentials in browser JavaScript

## Known limits before customer rollout
- One shared admin password; **no customer accounts or per-customer access isolation yet**. Do not share login with customers.
- First 100 devices only; no pagination yet.
- Live readings only; no historical charts, alarm configuration, ETA, AI assistant, or notifications yet.
- The provider may return location in a format not yet covered by the UI; adjust after a real-device check.
- No login rate limiter or persistent authentication store; use admin-only pilot and add identity provider + rate limiting before broad deployment.
- External map tile provider receives requests from the browser. If privacy requirements prohibit this, use a suitable private map provider.

## Deploy on Render
1. Create a **private GitHub repository** and upload the contents of this folder (not the ZIP itself). Do **not** upload API keys, `.env`, or credentials.
2. In [Render Dashboard](https://dashboard.render.com), choose **New > Blueprint**, connect the repository, and select `render.yaml`.
3. Select the paid **Starter** instance if prompted. Verify current Render pricing before approval.
4. Supply these secret environment variables in Render's protected environment settings: `ADMIN_PASSWORD` (a long, unique password), `TZONE_APP_ID`, `TZONE_APP_KEY`, `TZONE_APP_SECRET`. `SESSION_SECRET` is generated by the Blueprint.
5. Deploy. Open the assigned `*.onrender.com` URL, log in, and verify the real device. **Do not add DNS yet**.
6. In Render service **Settings > Custom Domains**, add `tracking.protempusa.com`. Render will show the exact DNS target.
7. In GoDaddy DNS for `protempusa.com`, **add a new CNAME record**: Name/Host `tracking`; Value/Points to = **the exact target Render displays**. Never change the existing `cloud` record, nameservers, MX, or other records. If a `tracking` record already exists, stop and inspect it first.
8. Wait for DNS/HTTPS verification in Render. Test `https://tracking.protempusa.com` and separately confirm `https://cloud.protempusa.com` still works.

**No deployment or DNS change has been performed by the creation of these files.**

## Local testing (optional)
Install Python 3.10+ and dependencies with `pip install -r requirements.txt`. Set `LOCAL_DEV=1`, `SESSION_SECRET`, `ADMIN_PASSWORD`, `TZONE_APP_ID`, `TZONE_APP_KEY`, and `TZONE_APP_SECRET` in your terminal (do not paste into shared logs). Run `python app.py`, then visit `http://127.0.0.1:5000`.

## Security notes
- The TZONE `/Identity` specification requires credentials in HTTPS query parameters. This backend does not log URLs, credentials, tokens, or API response bodies. Provider-side logging is outside our control.
- Keep the GitHub repository private, and never place secrets in source code or commit history.
- This pilot requires additional hardening (rate limiting, robust identity, audit logging, customer-level access control) before external customers can sign in.
